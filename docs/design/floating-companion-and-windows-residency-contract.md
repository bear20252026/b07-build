# 浮动 Companion 与 Windows 桌面常驻契约

**状态：** 实施中
**日期：** 2026-08-22

## 1. 两个呈现面必须分开

| 呈现面 | 用户目的 | 实现边界 | 是否等同于系统桌面常驻 |
| --- | --- | --- | --- |
| Companion 设置页 | 配置视觉、VRM、角色卡、TTS 与受限能力 | 既有三级设置页，保持不作为展示页 | 否 |
| 应用内浮动 Companion | 在首页直接看到、拖动与控制角色 | 前端固定呈现层；只存无秘密的本地展示偏好 | 否 |
| Windows 原生桌面 Companion | 主窗口隐藏后仍在 Windows 桌面显示角色 | 独立、固定标签的 Tauri 原生窗口；仅 Windows x64 | 是，且需真机验证 |

> “关闭主工作台”在启用了 Windows 桌面 Companion 的情况下表示隐藏主窗口，不表示退出进程；“退出 AI Work OS”必须销毁角色窗口并停止整个应用。未启用角色窗口时，关闭行为保持现有应用退出语义。

## 2. 首页浮动角色交互

首页角色默认只在 `visualEnabled=true` 时渲染。位置、路线和静止状态使用独立的本地展示偏好保存，不进入 Provider Profile、任务、事件、SQLite、交付包或返回 DTO。

| 操作 | 鼠标 / 触控 / 触控笔 | 结果 |
| --- | --- | --- |
| 拖动角色 | Pointer Events | 角色在当前应用视口内移动；拖动结束后保存归一化位置并切换到静止。 |
| 静止 | 明确按钮 | 保持当前用户放置的位置。 |
| 漫步路线 | 明确按钮 | 角色在应用视口安全区域内按预设“港湾”路线缓慢移动。 |
| 环绕路线 | 明确按钮 | 角色在应用视口安全区域内按预设环绕路径移动。 |
| 打开设置 | 明确按钮 | 打开既有 Companion 设置页；不把设置内容加入首页。 |

移动端、平板与桌面共享 Pointer Events，因此使用同一拖动协议。移动端不模拟 Windows 系统桌面驻留，只显示应用前台内的角色层。

## 3. Windows 原生窗口最小权限

原生 Companion 仅使用固定窗口标签 `desktop-companion` 和固定应用内 URL。前端不得传入任意 URL、窗口 label、路径、命令、端口或环境变量。允许的原生命令仅是显示角色窗口、恢复主窗口和关闭角色窗口；它们不授予 Shell、文件、屏幕、麦克风、自动启动或后台工具调用权限。

## 4. 语音与模型边界

角色可以显示 MiMo TTS 的连接状态，但不会随角色显示、拖动、路线或 Windows 驻留自动调用 TTS。只有用户在既有角色设置页显式开启语音，并在独立 API 窗口保存 MiMo 会话连接后，才允许明确点击的一次性试听。
