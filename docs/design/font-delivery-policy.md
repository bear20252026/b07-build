# 字体交付策略：性能优先，Apple 体验优先

## 当前默认实现

工作台的 `--font-ui` 不加载任何远程或打包字体资源。它将 `-apple-system` 与 `BlinkMacSystemFont` 放在首位，因此在 macOS、iOS、iPadOS 和对应桌面壳环境中，英文数字使用系统 San Francisco，简体中文使用系统苹方的字形回退。该策略不产生字体网络请求、资源解码或额外安装包体积。

| 平台 | 当前字体路径 | 资源成本 |
|---|---|---|
| macOS / iOS / iPadOS | 系统 San Francisco + 苹方 | 0 字体下载；使用系统缓存 |
| Windows | `Microsoft YaHei` / `Segoe UI` 回退 | 0 字体下载；使用系统缓存 |
| Android / Linux | 系统无衬线与可用 CJK 字体回退 | 0 字体下载；使用系统缓存 |

## 不采用的方案

项目不直接打包完整苹方字库或未审查来源的 DMG。完整 CJK 字库会显著增加应用的安装、更新和冷启动 I/O，且来源字体是否可跨平台再分发应由授权材料明确覆盖。

## 可选授权字体扩展

当具备明确允许 **Web、Windows、Android、Linux 与桌面应用再分发** 的字体授权时，可启用以下扩展，但应保持为可选构建目标：

1. 只提供 `Regular`、`Medium`、`Semibold` 三个必要字重。
2. 将许可字体转换或取得为 WOFF2；按 Latin、CJK 简体、繁体等 Unicode 范围拆分。
3. 在应用外部资产仓储保存原始字体；仅将审核后的子集化产物放入发布构建。
4. 使用 `@font-face` 的 `font-display: swap`，并在首屏仅预加载必需的 Regular 子集。
5. 保留当前 `--font-ui` 系统栈作为加载失败和离线回退。

> 不应为了字体视觉一致性而以阻塞首屏、嵌入完整 60 MB 以上 CJK 字库或取消系统回退为代价。系统字体是当前项目的性能基线；授权子集字体是可选增强层。
