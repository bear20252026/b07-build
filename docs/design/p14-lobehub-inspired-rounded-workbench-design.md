# P14：保持黑白主题的圆润 Workbench 精修设计

**状态：** 已设计，待实现

**基线：** `main` @ `1c832ca7583d0cf8dacf46e51735f722cf52bd44`；开始设计时工作树仅含 P14 调研文档。
**设计参考：** LobeHub 的“工作单元持续可见、导航/主画布/检查器分工、紧凑而分层的 AI 界面”原则；不复制 LobeHub Community License 源码。[1]

## 1. 不变量

本次变更是 Workbench 的**视觉与布局精修**，不是运行时、协议、数据库或第三方 Provider 改造。`App.tsx` 继续是 Gateway 附着、task/run 水合、审批与交付动作的状态 owner；`PreviewPanel` 继续只通过 Workbench client 消费 task/run 受控 DTO；Gateway、SQLite、文件内容和 API key 不进入 WebView。

| 类别 | 保持不变 | P14 可改变 |
|---|---|---|
| 颜色 | `theme-light` / `theme-dark` 的所有现有 token 数值，成功/警告/失败语义，黑白主基调 | 不改变 token 数值；仅在既有 token 的透明度组合和现有阴影语义下分配表面层级。 |
| 状态与安全 | task/run、审批、authority mode、Provider 连接、P13 文件清单/预览/diff/ZIP 交付的 HTTP 契约 | 仅改变这些对象的视觉顺序、间距与组件容器，不新增自动执行入口。 |
| 交互 | 左侧导航、主题切换、模型连接、提交、批准、恢复、文件/代码/差异/交付包标签 | 增强悬停、焦点、圆角和信息层次；全部保留真实 `<button>` / `<a>`。 |
| 平台 | Windows 桌面优先、现有 CSP、无 `unsafe-eval`、无新图标运行时 | 只改 React markup 与 CSS；不添加第三方前端依赖。 |

> **失败语义：** 如果视觉改动使工作区在 1120px 以上无法同时查看任务和检查器、使状态颜色失去文本标签、使焦点不可见、或引入任何状态/API 行为变化，则视为失败并回退相关布局修改；不能以视觉效果替代受控操作的清晰性。

## 2. 布局精修

现有三栏结构保留，但将“中间大留白 + 平面卡片”收束为稳定的操作桌面：标题栏成为轻量上下文栏；欢迎区与模型连接条共同构成任务首屏；运行时快照拥有独立柔和面板；事件流使用更圆润、低对比的连续列表；底部编辑器形成贴近主画布的浮动输入岛。

```
┌────────── 252 px ──────────┬────────── 主画布 ──────────┬──── 检查器 ────┐
│ 圆润品牌区                  │ 上下文标题栏               │ 任务文件标题   │
│ 主操作（新建任务）          │ 任务引导 + 模型 readiness  │ 分段标签       │
│ 工作区 / 设置导航           │ 受控运行快照               │ 圆润文件卡     │
│                              │ 连续执行时间线              │ 代码 / Diff     │
│                              │ 浮动任务输入岛              │ 交付 / 引用     │
└─────────────────────────────┴────────────────────────────┴─────────────────┘
```

## 3. 圆润度与表面层级

| 组件 | 当前问题 | P14 处理 |
|---|---|---|
| 应用外框与侧栏 | 分割线明确但表面连续性不足 | 保留分栏和宽度，使用既有 sidebar/panel token 形成两级表面；增加更大的局部圆角，不引入新颜色。 |
| 标题栏和状态 pill | 功能完整但布局偏紧 | 提高横向内边距与 pill 圆角，维持 status 文本、色点及安全文字。 |
| 工作区首屏 | 任务引导、模型条和快照彼此分离 | 使用统一垂直节奏、圆润容器和更清晰的卡片起止关系。 |
| 时间线 | 单卡片可读但略像独立列表 | 使用更圆角的卡片、轻微 hover、连续缩进与内部 metadata 层次，事件不改变。 |
| 输入区 | 已有浮层，但与内容区间隔不足 | 提升圆角、柔和边界与底部安全区，不改变提交或权限选择。 |
| 右侧检查器 | 文件/代码交付完整，但外层偏平 | 使 header、tabs、canvas 与文件/交付卡片共享圆润角度与细边框，保持只读/显式交付提示。 |

## 4. 实现范围

P14 优先改动 `apps/workbench/src/workbench.css`，必要时仅为主工作区增加**无状态的语义容器**。禁止改变主题 token 的十六进制值，禁止触及 `task-client.ts`、Gateway 路由、领域服务、Rust 代码和桌面 CSP。新增 CSS 必须使用已有 `--canvas`、`--sidebar`、`--panel`、`--border`、`--accent-*`、`--success-*`、`--warning-*`、`--danger-*` token。

## 5. 验收标准

| 验收项 | 判定方式 |
|---|---|
| 色彩保真 | Diff 中不修改 `theme-light` / `theme-dark` token 的数值；不新增任意品牌主色。 |
| 桌面任务可见性 | 1440px 视口同时显示侧栏、中部 task 画布和 P13 文件检查器。 |
| 小屏退化 | 既有 1120px / 820px / 620px 断点仍能阅读和提交任务；隐藏检查器时不丢失核心任务操作。 |
| 可点击性 | 所有导航、提交、审批、文件标签、交付按钮保留原按钮/链接语义和可见 focus ring。 |
| 安全回归 | 架构检查、TypeScript、Workbench build 和 P13 客户端/桌面安全契约通过；不添加前端依赖。 |

## 6. 原创 Agent 小玩偶系统

P14 将新增一个 **Agent Companion** 视觉层，仅作为工作台的情境提示与角色选择入口；它不代表真人、不替代权限状态、不承诺 Agent 可自主执行，也不读取任务文件、Provider、密钥或本地路径。用户可在工作区侧栏的“当前助手”卡片中选择不同风格，选择仅存在于 React 视图状态。

| 角色 ID | 名称 | 风格与稳定锚点 | 视觉用途 |
|---|---|---|---|
| `orbit` | Orbit | 黑白圆角桌面机器人；双圆眼、小耳机、柔和半 3D 黏土质感 | 默认 Build 同伴，强调“实现与交付”。 |
| `mori` | Mori | 单色毛绒云朵小精灵；圆形轮廓、短手、纸质便签 | Plan 同伴，强调“分析与规划”。 |
| `pixel` | Pixel | 像素化小猫机器人；方圆轮廓、微型显示面板、8-bit 简洁边缘 | Explore 同伴，强调“快速只读探索”。 |
| `sage` | Sage | 极简纸雕猫头鹰；圆形眼罩、折纸翼、浅浮雕质感 | Reader 同伴，强调“隔离阅读不可信内容”。 |

角色生成资产为无文字、正方形、透明背景或纯白/纯黑干净背景的独立 PNG。页面不显示任何上游 Logo、人物、角色名、LobeHub 品牌色或品牌服饰。所有角色缩略图将通过 React `<img>` 静态引入，`alt` 描述清晰，选择器为语义化 `<button>`；不使用远程 URL、Canvas、SVG 脚本、eval 或运行时图标库。

### 角色选择器布局

侧栏保留现有导航。`Sider` 底部的工作区摘要扩展为圆角“当前 Agent”卡片：左侧是当前小玩偶，右侧显示名称和当前 Profile；卡片下方提供四个等尺寸圆形选择按钮。选中状态保留既有 `--accent-soft` 与 `--accent-strong`，角色本身保持中性灰阶，以满足主界面黑白主题不漂移的约束。

### 颜色放宽边界

用户允许小幅调整色彩，但 P14 不改 `theme-light` / `theme-dark` token 数值。唯一允许的视觉变化是使用现有中性 token 和现有低饱和 accent/status token 的透明混合，以增强 surface 分层；角色资源维持灰阶，避免向主界面引入新的品牌主色。

### 角色资源验证记录

已检查两轮生成结果。四个角色的主体均符合原创、灰阶、多风格和无文字要求；但图像生成器未按要求完全移除绿色/洋红临时底色。P14 因此使用受控的离线色键透明化脚本，仅去除不可能属于灰阶角色主体的高饱和背景像素。该处理不读取用户文件、不联网、不修改任务文件；最终资源在进入 Workbench 前必须再次确认不包含可见的临时色键线条。

### 浏览器级初步验证

在本地 Workbench 的实际桌面渲染中，黑白工作区、任务首屏、模型 readiness 卡、运行时快照、活动时间线、底部输入岛和 P13 右侧任务文件检查器可同时显示。侧栏的 Orbit、Mori、Pixel、Sage 四个角色按钮均作为真实按钮出现，当前选择以既有 accent token 标示。此层只变更视觉状态；Build、Plan、Explore、Reader 的实际权限标签与提交路径仍独立存在，未被角色选择器替代。

### 交互与主题验证

在浏览器中选择 Mori 后，侧栏名称、描述与肖像即时更新，而 Gateway 启动、Provider 连接、Build/Plan/Explore/Reader 权限按钮、任务输入和 P13 文件检查器均未发生动作。随后切换至既有深色主题，主画布、圆润卡片、输入岛、右侧检查器与 Mori 灰阶角色均保持可读；未出现绿色、洋红或额外品牌主色。该结果确认 P14 角色选择与主题切换均保持为前端显示层，不改变任何受控执行边界。
