## 一、产品目标（商业级最佳产品）

**产品定位**：AI 工作操作系统（AI Work OS）——本地优先、云端可协作、跨文件/浏览器/软件/业务系统持续完成任务并交付可编辑成果的桌面 AI 产品。

**第一性原理**：`Outcome → Plan → Execute → Review → Deliver → Learn`（不是 Message → Response）。

**商业级判定标准**（缺一不可）：
1. **任务可靠性**：计划完成率 / 首次成功率 / 人工接管率 / 工具错误率 / 产物可编辑率 / 单位任务成本——用户少返工，而不是模型更会说。
2. **安全权限模型**：默认本地、最小权限、显式能力、审批高风险动作、可撤销、可审计、可恢复。
3. **可回放的事件协议**：Task/Plan/Tool/Approval/Artifact 全部结构化事件化，任务可恢复、过程可解释、企业可审计。
4. **可组合能力生态**：Provider / Capability / Surface 三类插件，MCP marketplace、Skills、Experts 版本化。
5. **企业级治理与成本透明度**：RBAC、审计、配额、组织级模型路由、用量预算（Local Free → Pro → Team → Enterprise → Marketplace → Model Gateway）。

## 三、整体框架结构（积木式，一文件一职责）

```
┌──────────────── React/TS 工作台（纯展示，参照 AionUi）────────────────┐
│  Sider │ Chat消息流 │ Preview多视图 │ Explorer │ SourceControl │ cron │
└──────────────┬──────────────────────────────┬─────────────────────────┘
         C6 事件订阅                      C1 invoke
┌──────────────▼──────────────────────────────▼─────────────────────────┐
│  TS 领域包（仅依赖 protocol port）                                     │
│  agent-runtime(DAG/子代理/上下文治理) · mcp-host(不可信扩展) ·           │
│  provider-sdk(ModelDriver+Router) · plugin-sdk · artifact-sdk          │
└──────┬──────────────────────────┬──────────────────────────────────────┘
  C3 JSON-RPC              C4 port           C2 HTTP/WS(token)
┌──────▼──────────────┐  ┌──────────▼───────────────────────────────┐
│ Rust 控制平面         │  │ Python sidecars                          │
│ 生命周期/崩溃恢复      │  │ document-worker(解析/OCR)                │
│ security(Hook链/权限) │  │ retrieval-worker(Embedding/RAG)          │
│ process-supervisor    │  │ speech-worker(STT/TTS)                   │
│ filesystem(工作树)    │  │ 127.0.0.1 + 短生命周期 token              │
│ proxy-gateway(路由)   │  └──────────────────────────────────────────┘
│ SQLite+append-only    │
└───────────────────────┘
```

### 关键设计决策（承前）
- **三语言边界**：Rust 做安全与边界、TS 做产品与生态、Python 做高变化 AI 能力——互不跨界。
- **唯一渠道**：C1 tauri invoke / C2 HTTP+WS / C3 JSON-RPC / C4 port / C5 进程内代理 / C6 事件订阅；UI 不直连 DB，Python 不反向控 Rust。
- **Claude Code 基线吸收点**：Hook 链入 `security`、上下文分层治理入 `agent-runtime`、子代理隔离入运行时、MCP 默认不信任入 `mcp-host`、工作树隔离入 `filesystem`、UI 解耦入 workbench。

## 四、研发优先级（近期冲刺顺序）
1. Rust `security`（Hook 链/权限）+ `proxy-gateway`（cc-switch 式进程内代理）
2. Rust↔Python 真实拉起接线（token 注入打通 C2）
3. `agent-runtime` 升级：子代理隔离 + 上下文分层治理（Claude Code 基线 2/3）
4. `mcp-host`（默认不信任 + 权限声明）
5. 事件协议契约测试（JSON Schema 校验）
