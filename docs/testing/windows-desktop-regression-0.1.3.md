# AI Work OS 0.1.3 Windows 桌面回归清单

**适用工件：** GitHub Actions Windows runner 构建的 `AI Work OS_0.1.3_x64-setup.exe`。  
**不适用：** 任何用户本机构建、旧 0.1.1/0.1.2 安装器或未带来源证明的文件。

> 本清单将“云端构建成功”与“Windows 实际运行通过”分开记录。前者只证明可重复打包；后者需要在安装器环境中执行以下场景。

| 场景 | 操作 | 预期结果 | 自动覆盖 |
|---|---|---|---|
| 版本与来源 | 在“已连接模型”复制本地诊断报告。 | 报告显示 `0.1.3`、40 位来源提交、无 API key、提示词、回复、图片数据或工作区路径。 | DTO 单测、桌面壳契约测试、云端 provenance。 |
| Provider 测试 | 使用有效 OpenAI-compatible 或 Anthropic-compatible 配置连接，再点“测试连接”和“流式发送”。 | 两个操作均使用同一原生会话；报告记录协议、脱敏 Base URL、模型、阶段、耗时和结果。 | Provider 账本单测、原生 Provider/Rust 测试。 |
| 图片错误定位 | 使用供应商确认不支持图片的模型发送 PNG/JPEG/WebP/GIF。 | 图片确实传递到 Provider；上游 404 显示 `provider-http-404-image` 兼容性说明，不称为本地拦截。 | Rust 多模态 payload 与 404 诊断测试。 |
| SearXNG 冷启动 | 选择“本地 SearXNG”，首次执行检索，再打开诊断报告。 | 不弹出 cmd/终端窗口；服务在应用内启动；报告显示 loopback 运行状态或可读失败分类。 | Rust loopback header、35 秒预算和状态查询测试。 |
| 混合检索 | 开启“混合检索”并问时效问题。 | 每个后端的成功/失败回执、来源计数和模型上下文活动可见；聊天正文不持久化原始网页全文。 | 混合检索去重/100 来源测试。 |
| 长会话 | 连续发送超过 60 条消息，向上阅读历史，再收到新回复。 | 已加载的历史不被跳回最近窗口；只有靠近底部时自动跟随；复制和向下跳转可用。 | 时间线窗口、历史与流式节流单测。 |
| 公式 | 发送包含行内、块级和复杂 TeX 的请求。 | KaTeX 按需渲染；无法解析的输入回退为可读文本，不使聊天白屏。 | 数学文本测试与生产构建。 |
| GitHub 协作 | 在聊天输入 `/github`，不输入令牌到聊天。 | 本地 GitHub 协作窗口打开并加载工作区状态；只有窗口内勾选确认才能 commit/push；取消不修改 Git。 | 命令解析与桌面壳契约测试。 |

## 云端验收记录

| 项目 | 记录方式 |
|---|---|
| 构建 | GitHub Actions `Windows desktop shell provenance` 成功运行号与工件 URL。 |
| 工件 | 下载后的文件名、字节数、SHA-256 与 `desktop-shell-manifest.json` 一致。 |
| 来源证明 | `gh attestation verify` 对工件、仓库和工作流均通过。 |
| 实机结果 | 每项填写通过、失败代码、Provider 协议/模型（不填 key）及可复制诊断报告。 |
