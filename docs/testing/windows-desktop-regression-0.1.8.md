# AI Work OS 0.1.8 Windows P1 回归清单

本清单验证 P1 的本地白盒工作流。普通聊天仍由 Tauri 原生 HTTPS/SSE 直接发送至用户选定的第三方 Provider；本轮不重新插入 Gateway，也不在安装包内提供显式 Gateway sidecar。

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 白盒项目记忆 | 打开“项目记忆” Inspector，不点击读取；随后选择工作区并点击“读取记忆”。 | 初次打开不发生文件 I/O；显式读取后仅显示当前工作区的 `AI_WORK_OS_MEMORY.md`。|
| 记忆提议与批准 | 输入一条记忆提议，查看预览，不勾选批准；随后勾选并批准。 | 未批准时绝不写文件；批准后内容仅以追加区块写入，既有内容不被覆盖。|
| 上下文预算 | 打开“上下文预算”，再显式点击读取项目记忆。 | 显示会话、草稿、附件元数据与记忆的本地**字符**投影；清晰声明不是供应商 token、费用或账单。|
| 检查点与恢复 | 为当前会话创建检查点，再恢复该检查点。 | 恢复创建新的本地会话；原会话与检查点不可被改写。|
| 分支与导出 | 从某条消息创建分支；分别导出 Markdown 和 JSON。 | 分支仅复制该消息以前的可见消息；导出没有隐藏 Provider context、搜索活动详情、密钥或 PAT。|
| 会话模型切换 | 在已有聊天顶部点击“模型”，切换厂商连接或手填模型并点击“使用此模型”。 | 仅后续发送使用显式选择；不改动连接地址、密钥或既有消息，不静默切换模型。|
| GitHub 预检 | 打开 `/github` 面板，读取状态并点击“运行变更预检”。 | 只在显式点击后运行固定 `git diff --check`；不执行任意项目脚本、不安装依赖、不调用模型、不读写或显示 PAT。|
| 显式推送 | 填写本地 PAT 与提交说明，但不勾选确认；随后勾选确认。 | 未勾选时提交/推送被拒绝；勾选后才允许本机 Git 提交和远程推送。PAT 不进入聊天、诊断或版本库。|
| 本地用量账本 | 完成连接测试、流式测试和至少一轮聊天后打开“本地用量账本”。 | 最多显示 128 条本机脱敏元数据，按 Provider/模型/会话聚合调用、耗时、首 token、失败与可见输出字符；不保存或显示正文、图片、端点、密钥、供应商 token/费用。|
| 云端来源 | 从 GitHub Windows runner 工件安装。 | 清单版本为 0.1.8、`canAutoStartGateway=false`、`bundlesExplicitGatewaySidecar=false`；SHA-256 与 SLSA provenance 均对应发布提交。|
