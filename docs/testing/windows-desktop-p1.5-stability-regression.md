# AI Work OS P1.5 Windows 实机稳定性回归清单

本清单用于 Windows 桌面端的真实人工验收。它不替代自动化测试，也不会收集或要求提交 API key、提示词、回复、图片、代理地址、工作区路径或 GitHub PAT。

> **验收边界：** 普通聊天必须保持 `WebView → Tauri invoke/events → Rust 原生 HTTPS/SSE → 第三方 Provider` 的直连路径。测试中不应出现用于普通聊天的 Gateway、代理 sidecar 或自动启动后台服务。

| 场景 | 操作 | 通过条件 | 禁止记录的内容 |
|---|---|---|---|
| Windows 系统代理 | 在已启用 Windows 系统代理的网络中，选择已连接 Provider 并发送一条无敏感测试问题。 | 请求能够由原生 Provider 客户端建立 HTTPS/SSE；若失败，错误提示可区分 DNS、TLS、连接、超时或上游拒绝。 | 代理地址、用户名、密码、密钥、问题与回答。 |
| 流式文本与首 token | 发送能产生较长回答的问题，观察文本持续出现和“跳到最新”按钮。 | 首 token 后逐步更新；用户停留在底部时自动跟随，向上阅读时不强制拉回底部；可主动跳到最新。 | 回答文本或推理正文。 |
| 长会话窗口化 | 在同一会话达到 60 条以上可见消息后继续聊天，并显式加载更早消息。 | 默认只渲染最新窗口；“加载更早消息”仅按主人点击展开；滚动、复制、分支和检查点仍可用。 | 所有消息正文、附件内容、搜索原始输出。 |
| 本地性能观察 | 在当前会话工具栏打开“性能观察”，完成一次聊天后重新打开。 | 只显示有界数值样本、持久化/流式/时间线耗时和可见窗口计数；关闭或打开面板不触发 Provider 请求、文件扫描或后台服务。 | Provider、模型、Base URL、文件名、路径、正文、图片、密钥。 |
| 内存与长期使用 | 连续切换多个会话、发送数轮流式回答、加载/收起早期消息，并在任务管理器中观察进程趋势。 | 内存不应因完整历史 DOM 常驻而持续线性增加；活动会话只保留最近 200 条，界面默认窗口化渲染。记录为“稳定 / 异常趋势”，不要记录聊天内容。 | 聊天正文、工作区路径、进程命令行、密钥。 |
| 深浅主题与减少动态 | 分别在明亮、深色和 Windows“减少动态效果”设置下打开会话、Inspector 和输入框。 | 文字对比清晰；Inspector 只包含标题栏、关闭按钮和独立滚动内容面；减少动态时不依赖进入动画完成操作。 | 无需收集任何内容。 |
| 检查点、分支与导出 | 创建检查点、从一条消息分支、恢复检查点并导出 Markdown/JSON。 | 原会话不被改写；恢复会新建会话；导出不包含隐藏 Provider context、活动详情、PAT 或密钥。 | 导出正文可由主人自行检查，不应上传给验收报告。 |
| GitHub 本地预检 | 打开 `/github` 面板，在已配置 PAT 的情况下显式运行预检。 | 仅运行固定 `git diff --check`；提交与远程 push 继续要求主人显式确认；PAT 不显示、不写入聊天、不进入模型上下文。 | PAT、远程地址凭据、代码私密内容。 |
| 项目工作台闭环 | 创建项目，在该项目选中状态下发起一轮聊天；打开项目页，查看关联会话，依次打开“项目文件”“项目产物”“终端计划”。 | 项目页只显示关联会话和 task/run 引用；文件、产物和终端在各自独立窗口显式打开，不会在打开项目页时扫描、预览或执行。 | 会话正文、文件路径、产物正文、终端输出。 |
| 本地知识库 | 从项目页打开“本地知识库”，主动粘贴文本或选择一个文本/代码文件，再按术语检索。 | 仅处理本次明确选择的资料；显示有界术语、来源预览和字节数；不会自动上传、递归扫描文件夹或自动加入 Provider 对话上下文。 | 原文件正文、绝对路径、API key、Provider 或模型信息。 |

## 建议的脱敏验收摘要

验收完成后，建议仅回传以下非敏感结论：桌面版本、来源提交、网络场景（系统代理开/关）、Provider 成功/失败分类、首 token 是否出现、长会话是否流畅、性能面板是否只显示数值、主题/减少动态是否正常、检查点/导出/GitHub 预检是否通过。若出现异常，只提供错误分类、发生步骤和是否可复现；不要提交凭据、文本或路径。
