## 2. 可本地化的产品模式

AFFiNE 将文档、白板、表格和资产表达为可组合的工作区构件，并强调把相关构件置于可持续操作的页面中。[1] 对 AI Work OS 而言，这不意味着把聊天窗口伪装成笔记软件，而是应把每一个受控任务中的**目标、执行状态、审批、产物与交付**组织为能在同一屏审阅的明确块。

LobeHub 的官方定位是组织 Agent 的招聘、调度和报告；与其照搬 UI 或服务端模型，本项目可采纳「任务上下文持续可见」这一原则。[4] 所有 Provider 请求仍由本机 Gateway 代表桌面壳发起，桌面 UI 只订阅任务事件与发出意图，不直接连接 Provider、SQLite 或系统进程。

| 体验模式 | P19 本地化约束 | 不可改变的架构边界 |
| --- | --- | --- |
| 工作区块与阅读顺序 | 以任务摘要、运行时间线、产物数量、待审批项和交付状态组成可独立扫描的块；每块只承担一种工作语义。 | 这些块只消费已存在的 DTO/事件；不得创建 Provider 或 SQLite 直连。 |
| 低干扰页面跳转 | 导航只显示稳定的高频入口；块内动作必须是显式意图，例如查看文件、查看交付或进入模型连接。 | 路由不携带密钥、API URL 或未审查的任务输入。 |
| Agent 任务可见性 | 明确显示任务状态和权限模式，避免把自动化误导为无限权限自治。 | 审批机制、执行策略与守护进程监督仍由既有 Gateway/Rust 控制面强制。 |
| 文件/交付审查 | 将文件、代码、差异、ZIP 和引用作为当前 task/run 的检查器对象，而不是聊天消息附件的无边界集合。 | 路径 containment、工作区账本、显式交付规则不变。 |

## 3. P19 候选实现方向

P19 拟实现一个原创的 **Task Storyboard**：在 Workbench 主工作区以块式方式呈现「任务上下文、执行进度、等待决定、已生成成果」的关联结构，并用轻量锚点在主工作区和右侧 Inspector 间跳转。它不是数据库、画布编辑器或新的 Agent 运行时；目标是在不增加状态源的情况下，提升用户对当前任务和可交付成果的可见性。

该方向优先于引入 AFFiNE/BlockSuite/LobeHub 的运行时依赖，因为后者会放大依赖体积、CSP 风险、数据模型耦合和许可证审计成本，且不能改善现有桌面受控执行链本身。

## 5. 浏览器级实现验证

在本机 Vite Workbench 预览中，P19 故事板位于模型就绪提示与既有运行快照之间，并与右侧 task/run 专属 Inspector 同时可见。无任务状态下，四块均显示为等待/只读语义：不会出现虚构的运行、文件或审批，也不会自动附着 Gateway。`查看成果` 是可点击控件，但仅把键盘焦点移到已有的右侧 Inspector；该动作未触发 Provider 请求、文件预览或 ZIP 创建。

该首屏验证证明 P19 的块式阅读顺序与既有三栏 Workbench 兼容：左侧承担稳定导航，中部承担任务上下文与运行说明，右侧继续承担受控文件/代码/差异/交付/引用审查。此验证不构成对任何上游视觉资产或源代码的复用。

补充交互验证：点击故事板“查看成果”后，浏览器焦点实际落在 `#task-inspector`，已有 Inspector 保持 `Files` 标签为活动标签。该验证确认此跳转不切换预览内容、不加载文件、不附着 Gateway，也不产生 Provider 请求。
