# Companion 首屏与 3D 呈现复核（2026-08-22）

## 实测范围

在云端 Chromium 的 877×748 视口中，打开工作区首页、设置浮层的“扩展与能力”二级页、以及 Companion Agent 三级页进行人工验证。

| 项目 | 复核结果 | 结论 |
| --- | --- | --- |
| 工作区首页 | 浏览器报告 `Pixels below viewport: 0` | 首页本身在当前视口无纵向滚动，仍只保留任务发起与按需设置入口。 |
| Companion 摘要 | 显示“当前可见：2D 动态玩偶（VRM 待导入）” | 不再把没有资产的状态称作已显示 3D 人物。 |
| Companion 三级页 | 浏览器报告 `Pixels below viewport: 0`；视觉、渲染、语音与四项高影响能力均在同一屏 | 默认控制面已压缩至首屏，且核心开关与状态无需滚动即可审查。 |
| 3D 选择 | 显示“VRM 模型尚未导入”“VRM 舞台（待导入模型）” | 当前无真实 VRM 模型。选择 3D 仅登记舞台请求，视觉呈现回退到已有 2D 动态玩偶。 |

> 结论：此前的“3D / VRM 舞台”是渲染意图而不是已加载的 3D 资产，造成了错误期待。本轮已把状态、说明与回退行为一致化。真实 VRM 人物仍需要后续通过本地、经来源/版权/大小/安全审查的模型导入流程实现，不能用空舞台或网络自动下载代替。
