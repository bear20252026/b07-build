# P6.7：开发自签名与 GitHub 构建来源证明

**状态：** 实现中，Windows 优先。

## 决策

本阶段把用户所说的“自签名认证 + GitHub 认证”明确拆分为两个彼此独立的机制：本机 **Authenticode 自签名** 用于开发学习时确认某个二进制副本由当前 Windows 用户证书库中的临时私钥签出；GitHub Actions **构建来源证明** 用于让下载者验证某个候选 ZIP 是否由 `bear20252026/b07-build` 的特定提交和工作流构建。它们均不等同于公开 CA 的发布者身份认证，且都不会自动信任 native bridge、安装 helper 或激活构件。

| 机制 | 产物/验证对象 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `sign-development-copy.ps1` | 由候选包提取出的新 `.exe` 副本和本地 receipt | 本机副本包含指定自签名证书；输入/输出摘要与收据一致 | 发布者真实身份、公开 Windows 信任、GitHub 构建来源、软件安全性 |
| `VERIFY-DEVELOPMENT-SELF-SIGNING.ps1` | 开发自签名目录 | 签名者 thumbprint、摘要、收据约束一致 | 根证书受信任、可安装、可发布、可提升 bridge trust |
| GitHub `actions/attest@v4` | 原始 `unsigned-candidate` ZIP | ZIP 与 GitHub Actions 工作流、仓库、提交 SHA、触发事件关联 | ZIP 无恶意、代码签名有效、发布者 CA 身份已验证 |

GitHub 说明，artifact attestation 通过 OIDC 和 Sigstore 建立来源声明，并记录相关工作流、仓库、提交与触发事件；其本身不是工件安全性的保证，使用者仍须定义并验证自己的信任策略。[1] [2]

## 实现边界

开发自签名脚本必须显式传入确认语句 `I_ACKNOWLEDGE_DEVELOPMENT_ONLY`；创建有效期 30 天、RSA-3072、SHA-256、不可导出的 `CurrentUser\My` Code Signing 证书。私钥既不会导出到 `.pfx`，也不会写入仓库。脚本签的是解压候选包后的 **新副本**，原始 ZIP、其内 `release-manifest.json` 和 `signingStatus = unsigned-candidate` 保持不变。

验证器以 allowlist 限制目录仅有 exe 与收据。它验证二进制摘要、签名者 thumbprint、证书自签名属性和收据的所有禁止提升字段。验证成功的 JSON 仍固定返回 `publicTrust: false`、`canInstall: false`、`canAutoTrust: false`、`canActivateComponents: false` 与 `canPromoteRelease: false`。

GitHub workflow 仅在手动触发或推送 `v*` 标签时，在 GitHub 托管的 `windows-latest` runner 构建原始候选包、执行既有只读候选验证器、上传 ZIP 与其 SHA-256 清单，最后对 ZIP 执行 `actions/attest@v4`。其权限严格为 `contents: read`、`id-token: write`、`attestations: write`；不会读取或保存代码签名凭据，也不调用本机自签名脚本。

## 使用步骤

本机开发时，先运行既有候选打包器并解压其 ZIP，然后运行：

```powershell
.\scripts\windows\sign-development-copy.ps1 `
  -CandidateBinary .\artifacts\windows-x64\awo-native-host-helper-0.1.0-windows-x64\awo-native-host-helper.exe `
  -AcknowledgeDevelopmentOnly I_ACKNOWLEDGE_DEVELOPMENT_ONLY
.\scripts\windows\VERIFY-DEVELOPMENT-SELF-SIGNING.ps1 `
  -DevelopmentDirectory .\artifacts\windows-x64\awo-native-host-helper-0.1.0-windows-x64\development-self-signed
```

运行 GitHub Actions 工作流后，下载相同的 ZIP，并使用精确仓库与工作流身份核验：

```bash
gh attestation verify awo-native-host-helper-0.1.0-windows-x64.zip \
  --repo bear20252026/b07-build \
  --signer-workflow bear20252026/b07-build/.github/workflows/windows-native-host-provenance.yml
```

GitHub CLI 文档指出，验证时至少应约束 owner 或 repository；进一步指定 signer workflow 能收紧工作流身份验证。[3]

## 禁止项

1. 不导出、上传、提交或共享自签名私钥、`.pfx`、PIN、token 或云签名凭据。
2. 不将自签名证书导入任何受信任根证书存储，也不在脚本中调用安装、启动、加载或信任提升操作。
3. 不将 GitHub Attestation 或自签名结果写入 P6.4 native host trust、P6.5 release-ready 或 P6.3 component activation 路径。
4. 不把 self-signed 输出提交为 GitHub Release，也不称作 `signed`、`trusted` 或 `released` 生产工件。
