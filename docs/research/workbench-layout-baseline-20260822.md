# Workbench 布局浏览器基线

**日期：** 2026-08-22
**验证对象：** 本地 `http://127.0.0.1:4173` 的真实 React Workbench 预览。

## 当前保留且正确的结构

首页保持低复杂度：左侧是产品、项目与动态助手，主区域提供任务意图、工作方式、模板、模型连接摘要和底部任务输入岛。模型、运行记录、浏览会话、角色目录和安全能力都没有进入首页。左下角设置入口会打开独立的圆角设置浮层，浮层包含左侧分类、右侧真实内容区、返回聊天动作与关闭动作；当前 Provider 连接三步流程中的按钮、服务商选择、API key 输入和已连接模型跳转均仍是可点击元素。

## 观察到的布局问题

当前首页的欢迎标题和四种工作方式卡片占用较大纵向空间，而连接摘要、显式工作方式解释、建议任务与输入岛继续向下堆叠，首屏操作密度偏散。设置浮层的左右分栏已存在，但左侧设置导航与底层全局侧栏在视觉上竞争注意力；右侧三步连接流程的 Provider 网格在桌面宽度下可进一步采用更清晰的“步骤导航 + 当前步骤内容”层级，以缩短扫描路径。

## 本轮不可回退条件

浮层必须继续是独立可关闭层，不能退化为首页原位替换。首页不得新增角色、审计、浏览控制或密钥管理。Provider 三步连接、角色候选、浏览会话、API 使用审计、任务意图和底部输入岛的真实回调与 Gateway 边界必须保持不变。视觉改造必须保留可见焦点、状态文字、`title` 提示、系统字体与 `prefers-reduced-motion` 支持。


## AFFiNE 布局研究与本地化边界

AFFiNE 将工作区作为文档与成员的组织容器，并区分本地与云端工作区；其公开资料同时将工作区设置作为低频管理区域。其仓库将自身描述为由可组合构件组成的工作空间，并采用 MIT 许可证。[1] [2] 本项目只吸收三项布局模式：工作区主面优先呈现当前工作对象；低频管理能力进入独立设置空间；复杂内容用可组合的独立视图/构件承载。

AI Work OS 不复制 AFFiNE 的品牌、文档/白板产品模型、云协作流程或视觉资产。它继续以“任务、项目、受控运行、Provider、审计、浏览会话”为真实对象，保持 Gateway 管道、显式操作者意图、API key 不持久化以及首页极简原则。

[1] [AFFiNE workspaces documentation](https://docs.affine.pro/core-concepts/elements-of-affine/workspaces)

[2] [toeverything/AFFiNE repository](https://github.com/toeverything/AFFiNE)


## 改造后桌面验证

改造后的首页在桌面预览中呈现为左侧导航、中央任务主画布、右侧当前上下文栏和底部任务输入岛。主画布承载目标标题、四种工作方式和三项任务模板；上下文栏承载第三方模型连接、明确工作方式、建议任务与设置提示。点击 `Plan` 后，主画布的选中态、右栏工作方式摘要和底部输入岛的工作方式标签同步更新为 `Plan · Review each step`，证明布局改造没有替换真实状态回调。

所有 Provider 连接、任务模板、建议任务、模式切换、键盘提示、权限选择和任务提交控件仍作为真实元素保留。设置入口仍位于左下角，未被移动到首页主画布中；下一步继续复核其独立浮层层级。
